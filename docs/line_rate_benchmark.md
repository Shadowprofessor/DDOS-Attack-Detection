# Line-Rate eBPF/XDP Ingress Benchmark & Architectural Guidance

## 1. Overview
The **Layer 1 eBPF/XDP flow probe** (`src/ebpf/xdp_flow_probe.c`) is designed to capture packet metadata at the earliest possible stage in the Linux networking subsystem: the network interface driver level before `sk_buff` allocation.

### The 40 Gbps Target vs. Cloud VPC Limitations
- **Bare-Metal / On-Premises (Native XDP)**:
  - Executes directly in the NIC driver's receive ring buffer (`XDP_FLAGS_DRV_MODE`).
  - Capable of sustaining up to **40 Gbps** line-rate ingress (59.52 Mpps for 64-byte packets) on enterprise NICs (e.g. Mellanox ConnectX-5/6 `mlx5`, Intel E810 `ice`).
  - Zero allocation overhead; metadata is extracted into a lockless BPF ring buffer, returning `XDP_PASS`.
- **Cloud VPC Environments (Generic XDP)**:
  - Most public cloud virtualized NIC drivers (AWS ENA, GCP virtio-net, Azure MANA / Accelerated Networking) do **not** support native driver-level XDP.
  - When deployed in cloud VPCs, the loader automatically logs a warning and operates in **Generic (SKB-based) XDP mode** (`XDP_FLAGS_SKB_MODE`).
  - Generic mode runs after the Linux kernel allocates the `sk_buff` structure. Throughput in generic mode performs **closer to libpcap** (~1 Gbps to 5 Gbps per core), **not** the 40 Gbps line-rate figure.
  - **Operator Guidance**: Enterprise production deployments requiring line-rate multi-10-Gbps ingress must be provisioned on bare-metal hardware with native XDP driver support.

## 2. Benchmark Architecture (`test_line_rate_throughput_manual`)

The benchmark harness tests:
1. **Ingress Ingestion Rate (Mpps)**: Measures maximum sustained packet rate without ring buffer drops.
2. **Backpressure & Drop Accounting**: Measures ring buffer drop count under synthetic oversubscription.
3. **Feature-Extraction Latency**: Per-packet userspace decoding and 77-feature flow accumulation latency.

### Benchmark Test Location
* File: `tests/test_ebpf_probe.py::test_line_rate_throughput_manual`
* Execution Gate: Hardware-gated via `@pytest.mark.skipif(not is_real_xdp_available(), ...)` so virtualized CI runners skip cleanly with explicit reasons.

## 3. Running the Benchmark (Manual Phase 4 Gate)

On an on-premise bare-metal Linux server with root privileges and a native XDP-supported NIC:

## 4. Bidirectional Flow Capture & Deployment Models

### Why XDP is Ingress-Only
In the Linux kernel network architecture, **XDP hooks execute strictly on packet ingress** at the physical/driver RX layer before SKB allocation. There is no egress hook in the XDP subsystem. Outbound packets generated by the host system leave via `dev_queue_xmit` on the network egress path, completely bypassing the XDP hook.

To observe both directions (forward and backward) of a network flow, two deployment topologies exist:

### Deployment Topology A: Network TAP / Switch SPAN Port (`deployment_mode='tap'`)
- **Topology**: The monitoring appliance runs `EbpfBackend` attached to a dedicated sensor NIC connected to an optical network TAP or switch SPAN / port mirror.
- **Packet Path**: The switch mirrors bidirectional traffic (both client→server and server→client) into the sensor's physical NIC.
- **Completeness**: Because both directions arrive at the sensor NIC's RX ring, the XDP ingress hook intercepts all packets.
- **Feature Completeness**: **1.0 (77 / 77 features populated)** — includes reverse inter-arrival times, backward byte/packet volumes, down/up ratios, and backward TCP flags.

### Deployment Topology B: Single Host Endpoint Protection (`deployment_mode='host_ingress'`)
- **Topology**: The probe attaches to a local server interface (e.g. `eth0`) on the protected host itself.
- **Packet Path**: Incoming attack traffic and client requests trigger the XDP ingress hook. However, the host's outgoing responses leave through egress and do not hit XDP.
- **Completeness**: Backward-direction packets are **genuinely not observed** unless a companion TC egress hook (`tc clsact egress`) is attached.
- **Feature Completeness**: **0.7013 (54 / 77 features populated)**.
  - **Populated (54)**: 5-tuple, protocol, flow duration, forward packet count, forward byte volume, forward inter-arrival times (IAT), packet length statistics, all TCP flags, active/idle windows, and forward bulk transmission rates.
  - **Zero-Filled (23)**: All 23 backward-specific metrics (`Total Backward Packets`, `Bwd Packets Length Total`, `Bwd Packet Length Min/Max/Mean/Std`, `Bwd IAT Total/Mean/Std/Max/Min`, `Bwd PSH/URG Flags`, `Bwd Header Length`, `Bwd Packets/s`, `Down/Up Ratio`, `Avg Bwd Segment Size`, `Bwd Avg Bytes/Packets/Bulk Rate`, `Subflow Bwd Packets/Bytes`, `Init Bwd Win Bytes`).
